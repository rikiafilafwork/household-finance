# Tabungan dengan Tujuan — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rekening bisa ditandai sebagai tabungan, saldonya dibagi manual ke tujuan bertarget. Ada rem "tabungan terpakai", alur "Gunakan", dan uang bebas yang tidak menghitung tabungan.

**Architecture:** Alokasi adalah label di atas `accounts.balance` (satu-satunya kebenaran uang). `savings_goals.allocated_amount` didenormalisasi dari log `savings_allocations` dan diubah atomik dengan pola kunci yang sudah ada: akun dulu (`LockAccounts`), lalu tujuan. Kondisi terpakai dihitung saat dibaca. Notifikasi dikirim oleh job setelah commit, dan dipicu event `updated` model `Account` saat saldo rekening tabungan berubah.

**Tech Stack:** Laravel 13 + Pest + Larastan (apps/api), React + TS + TanStack Query + shadcn/ui + Vitest (apps/web).

**Spec:** `docs/superpowers/specs/2026-11-27-tabungan-design.md`

## Global Constraints

- Uang = integer rupiah (bigint). Web dilarang memakai float (lint `make lint`).
- Semua data per user lewat trait `BelongsToUser`. Id milik user lain = 404, sama persis dengan id yang tidak ada.
- Setiap route `/api` baru wajib punya kasus di `tests/Feature/Isolation/DataIsolationTest.php` (penjaga route akan gagal kalau tidak ada).
- Penulisan saldo hanya lewat Actions di dalam `DB::transaction` + `LockAccounts`. Urutan kunci: **akun → tujuan (id menaik)**.
- Idempotensi tulis memakai `client_id` (UUID), sama seperti transaksi (Keputusan #15).
- Test API dijalankan di container: `docker compose exec -T app php artisan test --filter=<Nama>`. Test web: `pnpm --filter @personal-finance/web test -- <file> </dev/null`.
- Teks UI dalam Bahasa Indonesia. Label "Akun" diganti "Rekening"; path `/accounts` dan nama API tidak berubah.
- Satu task = satu GitHub issue = satu branch dan PR (`Closes #N`), self-merge setelah `make test` dan `make lint` hijau. Issue dibuat di milestone baru "Tabungan" saat eksekusi dimulai.

## Review Focus

1. **Banyak tambah alokasi bersamaan (klik ganda, dua tab).** Σ alokasi tidak boleh melebihi saldo. Kunci akun menserialkan semuanya (test concurrency di Task 3).
2. **Transfer keluar atau import yang menurunkan saldo rekening tabungan.** Peringatan terpakai harus muncul, karena semua jalur tulis yang menurunkan saldo memicu event `updated` (test di Task 5).
3. **Transaksi hasil "Gunakan" dihapus setelah tujuannya diarsip.** Alokasi kembali ke tujuan itu dan tujuan otomatis keluar dari arsip (test di Task 4).
4. **Saldo rekening tabungan 0 atau negatif.** "Belum dialokasikan" boleh negatif, tambah alokasi ditolak 422, dan halaman tidak crash (test di Task 2, Task 3, Task 8).
5. **Tenggat di bulan berjalan atau sudah lewat, dan alokasi ≥ target.** `monthly_needed` = sisa penuh, sisa penuh, dan 0 (test di Task 2).
